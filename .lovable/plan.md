## Goal

Make the **printed/PDF report** look like the Daily Collection Monitoring Dashboard mockup — Welile-branded header, 5 KPI cards, Tenant Daily Collection Tracker table, Agent Daily Collection Summary, Collection Overview donut, Monthly Collection Trend, and Top & Bottom Agents — instead of the current plain "Tenant Payments Report".

## Why a new generator

`src/lib/generateTenantOpsReportPdf.ts` builds a completely different layout (4 KPI cards + a single table of paid tenants over a date range). The new printout has a different shape, different data, and a fixed *single-day* focus. Trying to reshape the existing function would tangle two unrelated reports. We add a new, dedicated generator and wire the existing "Print Report" button to call it.

## What to build

### 1. New generator `src/lib/generateDailyCollectionReportPdf.ts`
A4 landscape PDF using `jspdf` (matches the wide mockup). Sections, top to bottom:

1. **Header strip** — Welile logo block left ("WELILE" + "TENANT PARTNERSHIPS"), bold centered title `DAILY COLLECTION MONITORING DASHBOARD` with subtitle "Track Daily Collections From Tenants", and a date chip on the right showing the selected day.
2. **KPI row (5 cards)** — Tenants Onboarded (Today), Tenants Paid For (Today), Collection Today (UGX), Collection This Month (UGX), Total Rent Paid (All Time). Each with icon glyph, label, big value, and the "+N vs yesterday" delta line in green/red.
3. **Tenant Daily Collection Tracker table** — same columns as on screen: #, Date, Agent, Tenant, Property/Landlord, Expected, Collected, Balance, Status (Paid/Partial/Missed badge), Payment Method, Remarks. Footer "DAILY TOTALS" row with expected/collected/balance sums. Auto-paginates, repeats header per page.
4. **Agent Daily Collection Summary table** — Agent, Tenants Onboarded, Tenants Paid For, Expected, Collected, Balance, Collection Rate %, Status (Good/At Risk). Bottom TOTAL row.
5. **Collection Overview (Today)** — donut placeholder rendered with two arcs (Collected vs Outstanding) using `jspdf` shapes + center "%" label, with a legend.
6. **Monthly Collection Trend (this month)** — simple line chart drawn with `jspdf` (axis, dotted grid, line points from the dashboard's existing `monthlySeries`).
7. **Top & Bottom Agents** — two side-by-side blocks: green "TOP PERFORMER" card and red "NEEDS IMPROVEMENT" card with name + collection rate.
8. **Footer** — "Generated by Welile Technologies Ltd. • <timestamp>" and "Page X of Y".

Color tokens reused from the mockup:
- Blue header chips `#2563EB`, green `#16A34A`, red `#DC2626`, amber `#F59E0B`, purple `#7C3AED`, slate `#0F172A`/`#64748B`.

### 2. Add a "Print Report" action inside the dashboard component
`src/components/shared/DailyCollectionMonitoringDashboard.tsx` already holds all the aggregated state (KPIs, `filteredRows`, `agentSummary`, donut split, `monthlySeries`, `topAgent`, `bottomAgent`). Add a small `Printer` button in the header row of the dashboard (next to the date picker) that:
- Calls `generateDailyCollectionReportPdf({ day, kpis, rows, agentSummary, donut, monthly, top, bottom })` with the current in-memory snapshot.
- Triggers download via existing `downloadPdfBlob` helper (pattern reused from `generateTenantOpsExtractPdf.ts`).

This guarantees the printed numbers always match what's on screen.

### 3. Wire the existing top-level "Print Report" button (Tenant Ops Dashboard)
In `src/components/executive/TenantOpsDashboard.tsx`, the toolbar's `handlePrintReport` currently calls `generateTenantOpsReportPdf`. We **leave that intact** (it's a different report — paid tenants over a range) and rename its label to "Tenant Payments Report" so users can tell the two apart. The new dashboard-style PDF lives on the Daily Collection card itself, where its single-day scope makes sense.

## Out of scope
- No DB changes, no new tables/columns/RPCs.
- No changes to the on-screen dashboard layout (already matches the mockup from the previous refactor).
- Real chart libraries (Recharts) won't be ported into the PDF — we use lightweight `jspdf` primitives so the PDF stays self-contained and fast.

## Files touched
- **NEW** `src/lib/generateDailyCollectionReportPdf.ts` — the new generator.
- `src/components/shared/DailyCollectionMonitoringDashboard.tsx` — add Print button + handler, pass current snapshot.
- `src/components/executive/TenantOpsDashboard.tsx` — relabel existing button to "Tenant Payments Report" to avoid confusion (one-line copy change).

## Risks
- jsPDF text/glyph rendering for icons: we'll use single-letter glyphs in colored circles (same trick the existing `generateTenantOpsReportPdf` uses) — no font embedding needed.
- Long tracker tables on busy days will paginate; header repeats per page so the report stays readable.
- `monthlySeries` is already fetched by the dashboard, so nothing new to query.
